# infra-print · 使用手册

## 1. 项目结构

```
infra-print/
├── component.yaml
├── assembly.yaml                     # default 角色；data_scopes: none；shell: py-render
├── buf.yaml / buf.gen.yaml
├── contracts/
│   ├── infra/print/v1/print.proto    # PrintService：Render/BatchGetTemplates/ListTemplates
│   ├── print.openapi.yaml
│   └── events/print.events.json      # 唯一一条：infra.print.rendered.v1（旁路）
├── gen/                               # buf/grpc_tools 生成，gen/ 本身不能有 __init__.py
│   └── infra/print/v1/print_pb2*.py

│   │   ├── main.py                   # besdk.run_standalone(create_module)

│   │   ├── render/                   # base.py（Renderer Protocol）/ pdf.py / zpl.py
│   │   ├── repo/                     # templates.py（版本管理）/ jobs.py（审计+outbox）
│   │   ├── service/                  # print_service.py：REST/gRPC 共用的编排层

├── migrations/
│   ├── 001_create_print.sql / .rollback.sql
│   └── 002_create_outbox.sql / .rollback.sql   # 只有 event_outbox，没有 event_inbox（本组件不消费）
├── tests/                             # 真实 Postgres/NATS，TEST_PG_DSN/TEST_NATS_URL 约定同 be-sdk-python
├── Dockerfile                         # 多阶段构建：build 阶段带 git（besdk 是 git+https 依赖）
├── Makefile
```

## 2. 功能详解

- **两条渲染路径共用 `render.get_renderer(channel)` 一个分流点**（`app/render/__init__.py`）：PDF 走 `WeasyPrintRenderer`（`jinja2.Environment(autoescape=True)` 渲染 HTML，`weasyprint.HTML(string=...).write_pdf()`）；ZPL 走 `ZplRenderer`（`autoescape=False`——ZPL 是纯文本指令 `^XA...^XZ`，HTML 转义会把指令本身改坏）。
- **模板渲染引擎选了完整 Jinja2，不是设计计划 §9 待决问题 3 倾向的"纯变量替换不做计算"**：真实的送货单/发票需要 `{% for item in items %}` 循环，纯变量替换做不到。"模板里不许有业务逻辑"这条边界改用代码审查守，不用语法层面的沙箱强制——同本项目"很多规则靠 `make gates`/review 而不是纯技术手段"的一贯做法。这是本组件实现时做的一个判断，写在 `app/render/pdf.py` 的注释里。
- **`put_template`/`rollback_template` 的写入顺序不能颠倒**（`app/repo/templates.py`）：必须先 upsert `print_templates`（父行），再 insert `print_template_versions`——后者有 `REFERENCES print_templates (id)` 外键，新模板第一次保存时反过来写会撞外键违例。
- **`record_job_and_publish` 必须在同一个事务里落 `print_jobs` 与 `event_outbox`**（`app/repo/jobs.py`，Outbox Pattern）：无论渲染成功还是失败都记一条 job（`status=SUCCESS/FAILED`），成功/失败都发 `infra.print.rendered.v1`。`preview`（`PrintService.preview`）明确不经过这条路径，不写 `print_jobs`。
- **`source_component` 字段是本组件加的一处对平台缺口的自我补偿**：`RenderRequest` 有 `source_component`（gRPC 调用方自报身份），因为本平台没有 gRPC 调用方身份自动注入机制，`infra.print.rendered.v1` 又需要一个有意义的来源标识——只能靠调用方自己如实填，本组件不校验它是否属实。REST 面走的是真人操作，`source_component` 留空，`actor` 改用 `besdk.scope_of().owner`。
- **`app/partition.py` 是全系统第一份 Python 版分区维护后台循环**：移植自 Go 版 `partition.go`/`monthly.go`（`infra-notification`/`erp-inventory` 的既有实现），`to_regclass` 判存在 + `CREATE TABLE ... PARTITION OF` 建分区的算法逐字对应，只是语言从 Go 换成 Python；建分区不需要 `ALTER TABLE ... OWNER TO`（沿用 Go 版已确认的 PostgreSQL 行为，与驱动语言无关）。
- **`app/migrate.py` 直接调 yoyo 的 Python API**（`yoyo.get_backend`/`read_migrations`），不 shell 出去调 yoyo 的 CLI；schema 隔离走 libpq 的 `options=-csearch_path%3D<schema>` 连接参数——真机验证过 yoyo 自己的内部记账表（`_yoyo_log`/`_yoyo_version`/`yoyo_lock`）也会正确落在这个 schema 里，不需要额外传 `--migration-table`。
- **迁移目录/`component.yaml` 都按 CWD 相对路径读，不按 `__file__` 反推**（`app/module.py`、`app/migrate.py`）：`pip install .`（非 editable）之后 `app` 包会被复制进 site-packages，`__file__` 往上反推目录就不再是仓库根——真机 build 镜像时确认过这一点，改成相对 CWD 之后本地开发与容器内（`WORKDIR /app`）都一致。

## 3. 完整契约清单

**gRPC `infra.print.v1.PrintService`**：

| rpc | 类型 | 幂等键 | 说明 |
|---|---|---|---|
| `Render` | 命令（无副作用） | **不需要**（本组件是纯函数） | `template_id` + `data_json` + `source_component` → `content` + `content_type` |
| `BatchGetTemplates` | 读 | — | 防 N+1 |
| `ListTemplates` | 读 | — | `channel` 筛选 + 游标分页 |

**REST**（`/infra/print/**`）：

| 路径 | 权限键 | 说明 |
|---|---|---|
| `POST /render` | `infra.print.render` | 前端直接要预览/打印时用 |
| `GET /templates` | `infra.print.template.view` | 模板清单 |
| `GET /templates/{id}` | `infra.print.template.view` | 模板详情 |
| `PUT /templates/{id}` | `infra.print.template.edit` | 上传新版本 |
| `POST /templates/{id}/rollback` | `infra.print.template.edit` | 回滚到指定历史版本 |
| `POST /templates/{id}/preview` | `infra.print.template.edit` | 用样例数据预览，不写 `print_jobs`（本组件自己的判断：预览是编辑流程的一部分） |

**发布事件：** `infra.print.rendered.v1`（旁路，唯一一条）。
**消费事件：** 无。

详细字段与判据见 [`docs/design/infra-print.md`](../../../../docs/design/infra-print.md)。

## 4. 数据模型

| 表 | 分区 | 说明 |
|---|---|---|
| `print_templates` | 不分区 | 模板当前版本；`version` 兼做业务版本号与乐观并发计数器 |
| `print_template_versions` | 不分区 | 历史版本，只增不改；`(template_id, version)` 唯一索引 |
| `print_jobs` | 月 | 唯一无限增长的表，全套 §11.2.1 强制字段；只有它 `ALTER TABLE ... OWNER TO infra_print_rw`（分区表才需要） |
| `event_outbox` | 周 | 标准表，**没有 `event_inbox`**——本组件不消费任何事件 |

**实测验证**（真实 Postgres + 真实 NATS + 真实 WeasyPrint，非 mock）：模板 CRUD/版本递增/回滚、`batchGet` 省略查不到的 id、游标分页排他性、`record_job_and_publish` 事务性、真实渲染出带中文的 A4 PDF 并用 `pdftotext` 确认无乱码、ZPL 通道纯文本替换、模板不存在/已停用/渲染语法错误三条失败路径都正确落 `FAILED` job、`preview` 不写 job、真实 gRPC in-process server 调用（`Render`/`BatchGetTemplates`/`ListTemplates`）、真实 JWT + bundle 轮询的 HTTP 权限判定链路（401 未带 token/403 无权限/200 真实渲染）、周/月分区维护幂等、迁移连跑两次幂等、Docker 镜像内真实渲染确认 CJK 字体链路。

## 5. 开发

```bash
cd components/infra/print
uv venv .venv --python 3.12
uv pip install -e . --python .venv/bin/python3

export TEST_PG_DSN="postgres://postgres:<密码>@localhost:5432/brickkit_db"
export TEST_NATS_URL="nats://localhost:4222"
.venv/bin/python3 -m pytest -v
```

跑测试前先把 schema 建出来（管理员账号，不是 `infra_print_rw`——建分区之类的 DDL 需要建表权限）：

```bash
export DATABASE_USER=postgres DATABASE_PASSWORD=<密码> DATABASE_HOST=localhost DATABASE_PORT=5432 \
  DATABASE_NAME=brickkit_db PG_SCHEMA=infra_print
.venv/bin/python3 -m app.migrate apply
```

`gen/` 下的 gRPC 桩代码用 `grpc_tools.protoc` 重新生成：

```bash
.venv/bin/python3 -m grpc_tools.protoc -I contracts -I .venv/lib/python3.12/site-packages/grpc_tools/_proto \
  --python_out=gen --grpc_python_out=gen --pyi_out=gen contracts/infra/print/v1/print.proto
```

`tests/test_http_routes.py`/`test_grpc_server.py` 用真实的本地 JWKS/bundle 服务器（`tests/authz_helpers.py`，移植自 `be-sdk-python` 自己的测试夹具）与真实 grpc.aio in-process server，不直接调 handler 函数——这是本项目端到端测试的一贯写法。测试之间用带时间戳的 id 隔离；`print_templates` 是全表共享（不像 outbox 能挑中立 schema躲开），分页测试要按自己的 id 集合过滤断言，不能假设自己是表里唯一的数据（`test_repo_templates.py` 的既有教训）。

## 6. 排障

| 症状 | 根因 | 修法 |
|---|---|---|
| 中文 PDF 提取出来是乱码或重复文字，不是简单的方框 | 容器里只装了 `libpango`/`libcairo`/`libgdk-pixbuf`，没装 CJK 字体，WeasyPrint 退化到 `DejaVu-Serif` | 确认镜像装了 `fonts-noto-cjk` + `fontconfig` 并跑过 `fc-cache -f`（`Dockerfile` 已含），模板显式写 `font-family: "Noto Sans CJK SC"` |
| `python -m app.migrate apply` 报 `relation "yoyo_lock" does not exist` | 连去了错的数据库（比如 `postgres` 库而不是 `brickkit_db`）——schema 找不到，yoyo 的内部记账表自然也建不出来 | 确认 `DATABASE_NAME=brickkit_db`（真机验证时踩过这个坑） |
| `pip install .` 报 `Cannot find command 'git'` | `besdk` 是 `git+https://...` 依赖，容器里没装 `git` | Dockerfile 用多阶段构建，`git`/`build-essential` 只留在 build 阶段 |
| 渲染接口本地开发时一直 403 | 没配 `iamJwksUrl`/`authzBundleUrl`——阶段一遗留的 fail-closed 默认行为 | 配置这两项指向真实运行的 `infra-iam-casdoor`/`infra-authz`，或在测试里用 `tests/authz_helpers.py` 起本地假服务器 |
| `create_module`/`app.migrate` 里读不到 `migrations/` 目录 | 用 `pip install .`（非 editable）之后从别的 CWD 启动进程 | 迁移目录与 `component.yaml` 都按 CWD 相对路径读，启动前 `cd` 到仓库根（容器里 `WORKDIR /app` 已经是） |
