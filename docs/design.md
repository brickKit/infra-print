# infra/print 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、规则、命令、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。跨组件的规则在装配项目的协议 10（打印与渲染）与协议 17（资源上限）。规则少，只有这一份文档。

## 边界

纯渲染服务：模板版本 + 调用方给的数据 → PDF（以后还有 ZPL）字节流。

| 不在这里 | 归谁 |
| --- | --- |
| 业务数据、按权限裁剪数据 | 调用方：数据进来之前已按调用者的权限与字段资格处理（协议 10） |
| 保存正式单据的输出、重打计数 | 调用方（存为附件，协议 12） |
| 连接现场打印机 | `integration/print-agent`（远期，向本组件拉取任务） |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 模板 | 一种单据的版式：身份（如 `invoice`）、引擎、语言 | `template` |
| 模板版本 | 模板的一次不可修改的内容：版本号、摘要（内容与字体的规范摘要）、状态；客户修改产生新版本 | `template_version` |
| 视图模型 | 调用方给的数据：已格式化的字符串（日期、金额、大写），按模板版本声明的 JSON Schema 校验 | `data` |
| 渲染 | 一次模板版本 + 数据 → 输出 | `render` |
| 渲染上限 | 每次渲染的时间、内存、输出大小，以及进程内同时渲染的个数 | 配置项 |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `template` | 模板：身份、名称、引擎、当前版本 | 停用，不删除 |
| `template_version` | 版本：模板、版本号、内容、数据的 JSON Schema、摘要、来源（随组件提供或客户修改）、状态 | 永不修改，不删除 |

随组件提供的模板（本版只有账单 `invoice`）在启动时按摘要登记：同一摘要已存在就不动，内容变了登记为新版本，不覆盖客户改过的。字体随镜像提供，属于模板版本的一部分（摘要包含字体文件的摘要）。

## 规则

- **不读业务数据**：没有数据库以外的数据访问，不调业务组件。
- **确定性**：同一模板版本与同一数据得到逐字节相同的输出。字体随版本固定；模板不能访问网络与文件系统（只读模板版本自己的资源）；时间、语言、时区、数字格式由调用方在数据里传入；PDF 的元数据（创建时间、文档 ID）固定或从数据摘要派生，不用当前时间。
- **模板不做业务计算**：只填视图模型里的字段；数据先按模板版本的 JSON Schema 校验，不合格答 `VALIDATION_FAILED`，不渲染。
- **资源上限**：渲染在独立的子进程中执行（不占事件循环，崩溃不拖垮进程）；每次渲染有超时（缺省 10 秒）、内存上限（缺省 512 MiB，子进程的 `RLIMIT_AS`）、输出上限（缺省 3 MiB：一个 gRPC 消息装得下，SDK 用 gRPC 缺省的 4 MiB 消息上限；更大的文档要流式方法，以后）；进程内同时渲染的个数有上限（缺省等于 CPU 数），超出时排队，排队超过期限答“资源不足”（协议 17）。超时与超内存的子进程被杀掉，答 `RENDER_LIMIT_EXCEEDED`。
- **只渲染**：重打标“副本”由调用方传入（`copy`，印在视图模型之外），本组件不计数。版本传 0 用当前版本，回答带实际用的版本与摘要，调用方记下、之后照传。

## 事件

无。

## 依赖

身份、授权（必需）。渲染的数据由调用方提供，没有业务依赖。

## 实现状态

实验第 7 步（Python）：随组件提供的账单模板与版本登记、渲染 PDF、渲染上限、模板的读取与预览。答“能力不支持”的：模板的在线维护、ZPL、现场打印的任务。

## 部署与替换

CPU 与内存突发；有资源上限；适合外壳（`be/py-render`）但要单独预算（协议 17）。渲染引擎可替换：引擎是模板的属性，新引擎以新模板版本引入，旧版本仍按旧引擎渲染。适用协议 10、17。

## 验证故事

| 故事 | 本版 |
| --- | --- |
| 同一模板版本与数据得到同样的 PDF | L2 |
| 渲染超时被限制，进程不受影响 | L2 |
| 模板修改后重打旧发票按原版本 | 在线维护本版不做；版本登记的规则在 L2 验证 |

## 未决问题

- **渲染引擎**：候选是 WeasyPrint（HTML 与 CSS 分页媒体，客户能改的是 HTML）与 Typst（排版系统，生成快、版式精确，模板不是 HTML），HTML 加无头浏览器因内存与镜像体积排在后面。按知识库“打印与单据模板”的比较，在 T7.7 用账单模板实测：单张耗时与 CPU、内存峰值、逐字节确定性、中文与西文字符的嵌入（`pdffonts`），在性能电源模式下成对比较后选定，结论交知识库。
- 模板语言的安全：客户可改的模板以后才开放；开放时按知识库的“模板注入”四件事做（受限的模板语言、隔离的渲染进程、编辑要审批审计、版本跟进安全修复）。
